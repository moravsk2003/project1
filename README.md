# Generative Building Design AI

**Generative Building Design AI** — дипломний Java-застосунок для автоматичного проєктування, оцінювання та оптимізації просторових будівельних структур із використанням методів штучного інтелекту.

Проєкт розроблений у межах дипломної роботи на тему:

> **«Розробка генеративної моделі для автоматичного проектування та оптимізації будівель і споруд з використанням штучного інтелекту»**

---

## Overview

Цей проєкт є дослідницьким програмним прототипом генеративної системи, яка може автоматично створювати будівельні структури, перевіряти їхню фізичну коректність та покращувати результат за заданими критеріями.

Як формалізоване середовище для експериментів використовується модель будівництва, натхненна механіками гри **Rust**. Таке середовище добре підходить для тестування AI-підходів, оскільки має чіткі правила побудови: сітку, поверхи, будівельні блоки, сокети, колізії, стабільність, матеріали, вартість елементів та оцінку захищеності конструкції.

У межах цього проєкту Rust-подібна модель розглядається не як ігрова мета, а як контрольоване симуляційне середовище для задачі генеративного проєктування. Система працює зі спорудою як із набором взаємопов’язаних елементів, де кожен блок має позицію, орієнтацію, геометрію, матеріал, точки з’єднання та вплив на загальну стабільність конструкції.

Головна ідея проєкту полягає в тому, щоб AI не просто випадково розміщував блоки, а поступово навчався створювати структури, які є фізично валідними, зв’язними, функціональними та оптимізованими за кількома показниками.

---

## What the project does

Система дозволяє:

- створювати будівельні структури вручну через JavaFX-інтерфейс;
- автоматично генерувати споруди за допомогою AI;
- перевіряти валідність розміщення будівельних елементів;
- виявляти колізії між блоками;
- розраховувати стабільність конструкції;
- видаляти нестабільні елементи;
- аналізувати зв’язність споруди;
- оцінювати логістику та доступність зон;
- оцінювати захищеність ключових елементів;
- порівнювати різні згенеровані варіанти;
- зберігати результати навчання та параметри моделей.

---

## Core idea

Будівля в системі представлена як тривимірна структура, що складається з окремих конструктивних елементів.

Кожен елемент має набір характеристик:

| Property | Description |
|---|---|
| Type | Тип будівельного блока: фундамент, стіна, перекриття, об’єкт тощо |
| Position | Координати елемента в межах просторової сітки |
| Floor | Рівень або поверх, на якому розміщений елемент |
| Rotation | Орієнтація блока у просторі |
| Geometry | Форма елемента та його collision-полігон |
| Material | Матеріал або рівень міцності елемента |
| Sockets | Точки з’єднання з іншими блоками |
| Stability | Внесок елемента у фізичну стійкість конструкції |
| Cost | Умовна вартість використаного ресурсу |

Після кожної дії система перевіряє, чи може новий елемент бути доданий до конструкції. Для цього враховуються фізичні обмеження, наявність опори, коректність з’єднання через сокети, відсутність колізій та вплив на загальну стабільність споруди.

## AI generation approaches

У проєкті реалізовано два незалежні підходи до автоматичного створення конструкцій.

### Reinforcement Learning

Перший підхід базується на навчанні з підкріпленням.

RL-агент будує споруду покроково. На кожному кроці він аналізує поточний стан конструкції, обирає дію, намагається розмістити новий елемент і отримує нагороду або штраф залежно від результату.

Дія агента розділена на кілька послідовних фаз:

| Phase | Meaning |
|---|---|
| Type | Вибір типу будівельного елемента |
| Floor | Вибір поверху |
| Tile | Вибір позиції на сітці |
| Rotation | Вибір орієнтації |
| Aim | Точне позиціонування всередині тайла |

Такий multi-discrete підхід зменшує складність простору дій і дозволяє AI приймати рішення поетапно, а не перебирати всі можливі комбінації одразу.

### Evolutionary Algorithms

Другий підхід базується на еволюційних алгоритмах.

У цьому режимі кожна споруда розглядається як окремий варіант рішення. Система створює популяцію таких варіантів, оцінює їх, відбирає найкращі, застосовує мутації та поступово покращує якість наступних поколінь.

Еволюційний модуль підтримує:

- адаптивну мутацію;
- перезапуск частини популяції при стагнації;
- захист від ситуації, коли надмірна мутація руйнує всі вдалі рішення;
- генерацію нових варіантів із гарантованою наявністю ключових елементів.

## Optimization criteria

Згенеровані споруди оцінюються не за одним параметром, а за набором критеріїв.

| Criterion | Description |
|---|---|
| Cost | Сумарна вартість використаних матеріалів |
| Stability | Фізична стійкість конструкції |
| Raid Resistance | Складність доступу до важливих зон |
| Logistics | Зручність переміщення всередині структури |
| Connectivity | Відсутність ізольованих фрагментів |
| Working Area | Раціональність використання внутрішнього простору |
| Validity | Відповідність правилам розміщення та фізичним обмеженням |

У дипломному контексті ці критерії використовуються як спрощена модель багатокритеріальної оптимізації будівельних структур. Вони дозволяють оцінити не лише факт побудови споруди, а й її якість з погляду вартості, функціональності, зв’язності та стійкості.

---

## Important note

Цей проєкт не є повноцінною CAD/BIM-системою для реального будівництва. Він не враховує реальні будівельні норми, інженерні комунікації, кліматичні фактори, нормативні навантаження або кошторисну документацію.

Основна цінність проєкту — демонстрація того, як методи штучного інтелекту можуть застосовуватися для автоматичного створення та оптимізації просторових конструкцій у контрольованому середовищі.

Проєкт можна розглядати як основу для подальших досліджень у напрямі генеративного проєктування, автоматизованого планування, багатокритеріальної оптимізації та AI-assisted design.
